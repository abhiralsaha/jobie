JOBIE PROJECT DETAILS
=====================

This document describes the current runtime. See README.md for setup and
HOW_TO_TEST.txt for the operational checklist.

1. PURPOSE AND SAFETY
---------------------

Jobie monitors configured public LinkedIn guest-search results, stores matching
records in Supabase PostgreSQL, and sends Telegram notifications. It can also
accept authenticated manual records or jobs from an authorized JSON feed.

The workers do not log in to LinkedIn, use account cookies or credentials,
bypass rate limits/CAPTCHAs/checkpoints, fill application forms, or submit
applications. The guest endpoint is not an official LinkedIn API; results and
access may change. Use permitted sources and follow their terms.

2. DATABASE AND CONFIGURATION
-----------------------------

`app/config.py` loads `.env`. `SUPABASE_DB_URL` is required and must be a
PostgreSQL/Supabase connection string. `app/db.py` uses a thread-safe psycopg2
connection pool and initializes the required tables in Supabase. Persistent
tables include `jobs_seen`, `jobs_applied`, `alerts_sent`, `seen_jobs`,
`search_runs`, `keep_alive_pings`, `digest_runs`, and `manual_digest_runs`.

The current runtime has no SQLite database, `DATABASE_PATH`, or `DB_PATH`
setting. Do not document or configure a local `jobie.db` file.

3. TWO WORKERS
--------------

A. Main search/API worker: `app.linkedin_fresh_jobs:app`
   - Local address: `http://127.0.0.1:8000`.
   - Render start command: `python -m uvicorn app.linkedin_fresh_jobs:app --host 0.0.0.0 --port $PORT`.
   - Searches the configured lookback window, stores/deduplicates jobs in
     `seen_jobs`, records search runs, and sends immediate or digest alerts.
   - Provides `/health`, authenticated `/fresh-jobs`, `/digest/send`, and
     `/keep-alive`.

B. Ultra-fresh watcher: `python -m app.fresh_watcher`
   - Runs as a separate process and Render Background Worker.
   - Render start command: `python -m app.fresh_watcher`.
   - Checks the last `FRESH_WATCHER_LOOKBACK` seconds (120 by default) about
     every `FRESH_WATCHER_INTERVAL` seconds (60 by default).
   - Uses a dedicated `FRESH_WATCHER_BOT_TOKEN`/
     `FRESH_WATCHER_CHAT_ID` pair, falling back to the main Telegram pair.
   - Uses PostgreSQL `seen_jobs` for restart-safe deduplication, retry and
     circuit-breaker behavior, and no HTTP API of its own.

The separate import API is `app.main:app`, normally port 8001 when the main
worker occupies port 8000. It owns `/health` and authenticated `/jobs/import`.
The optional authorized-feed connector posts to that endpoint.

4. MAIN WORKER BEHAVIOR
-----------------------

Defaults from current configuration include:

- `LINKEDIN_POLL_INTERVAL_SECONDS=600`.
- `LINKEDIN_LOOKBACK_HOURS=24`.
- `LINKEDIN_MAX_SEARCH_PAGES=2`, capped at ten by the worker.
- `RECENT_JOB_WINDOW_SECONDS=180`.
- `DAILY_DIGEST_TIME=18:00` in `Asia/Kolkata`.

The main worker only accepts valid LinkedIn HTTPS job links, rejects missing,
future, or out-of-window timestamps, and alerts once for each newly inserted
job ID. Scheduled digest and manual-send limits are persisted in PostgreSQL.
Search and digest coverage is bounded by the public endpoint and page cap; it
is not exhaustive.

5. IMPORTANT SETTINGS
---------------------

Required/common:

- `SUPABASE_DB_URL`: pooled Supabase PostgreSQL URL.
- `JOBIE_API_TOKEN`: strong bearer token for protected endpoints.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`: main outbound Telegram pair.
- `LINKEDIN_SEARCH_KEYWORDS`, `LINKEDIN_SEARCH_LOCATION`: search settings.

Main worker options include `LINKEDIN_POLL_INTERVAL_SECONDS`,
`LINKEDIN_LOOKBACK_HOURS`, `LINKEDIN_MAX_SEARCH_PAGES`,
`RECENT_JOB_WINDOW_SECONDS`, `DAILY_DIGEST_TIME`,
`DAILY_DIGEST_TIMEZONE`, `MANUAL_DIGEST_MAX_PER_DAY`, and
`MANUAL_DIGEST_COOLDOWN_SECONDS`. Optional rolling digest bot pairs use the
`TELEGRAM_DIGEST_*` settings.

Watcher options are `FRESH_WATCHER_BOT_TOKEN`, `FRESH_WATCHER_CHAT_ID`,
`FRESH_WATCHER_INTERVAL`, and `FRESH_WATCHER_LOOKBACK`. `LINKEDIN_PROXY_URL`
is optional; use only a proxy you are authorized to use.

Authorized feed options are `AUTHORIZED_JOB_FEED_URL`,
`AUTHORIZED_JOB_FEED_TOKEN`, `JOBIE_API_URL`, and `FEED_POLL_SECONDS`.

6. RUNNING AND DEPLOYMENT
-------------------------

Local commands:

    .\.venv\Scripts\python.exe -m uvicorn app.linkedin_fresh_jobs:app --host 127.0.0.1 --port 8000
    .\.venv\Scripts\python.exe -m app.fresh_watcher
    .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001

The last command is optional. On Render, create separate Background Worker
services using the two Render start commands in section 3. Set environment
variables in Render rather than committing secrets. `runtime.txt` pins Python
3.14.3.

7. FILE REFERENCE
-----------------

- `app/linkedin_fresh_jobs.py`: main search worker and API routes.
- `app/fresh_watcher.py`: separate ultra-fresh watcher process.
- `app/main.py`: authenticated import API.
- `app/db.py`: Supabase/PostgreSQL pool and schema initialization.
- `app/config.py`: environment-backed settings.
- `app/messaging.py`: outbound Telegram alerts and digests.
- `scripts/poll_authorized_feed.py`: optional authorized-feed client.
- `tests/`: automated checks.
- `.env.example`: sanitized environment template; replace every placeholder.

Keep services bound to localhost in development, use HTTPS remotely, protect
database URLs and tokens, and review listings before manual action.
