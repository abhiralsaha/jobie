JOBIE: SETUP, TESTING, AND OPERATION GUIDE
=========================================

1. CURRENT RUNTIME
------------------

Jobie has two separate long-running workers:

- Main search/API worker: `app.linkedin_fresh_jobs:app`.
- Ultra-fresh watcher: `python -m app.fresh_watcher`.

Both use Supabase PostgreSQL through `SUPABASE_DB_URL`. The database schema is
created on startup; this current runtime does not use SQLite, `DB_PATH`, or a
local `jobie.db` file.

The workers search LinkedIn's public guest results without logging in. They do
not use credentials or cookies, bypass controls, fill forms, or submit
applications. Search results are bounded and may be incomplete. Follow the
source site's terms and do not attempt to bypass blocks or challenges.

2. INSTALL AND CONFIGURE
------------------------

From the repository folder in PowerShell:

    python -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    Copy-Item .env.example .env
    notepad .env

Required settings include:

    SUPABASE_DB_URL=postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres
    JOBIE_API_TOKEN=<at-least-32-character-random-token>
    TELEGRAM_BOT_TOKEN=<BotFather-token>
    TELEGRAM_CHAT_ID=<private-chat-id>
    LINKEDIN_SEARCH_KEYWORDS=software engineer
    LINKEDIN_SEARCH_LOCATION=Gurugram, Haryana, India

The ultra-fresh watcher can use a separate bot:

    FRESH_WATCHER_BOT_TOKEN=<optional-BotFather-token>
    FRESH_WATCHER_CHAT_ID=<optional-private-chat-id>

If its dedicated pair is empty, it falls back to the main Telegram pair. Keep
all tokens, the Supabase URL, and `.env` private. Create the Telegram bot with
@BotFather and send it `/start` before testing delivery.

Generate a token locally without putting it in this guide:

    .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"

3. START BOTH WORKERS
---------------------

Use separate PowerShell windows:

    .\.venv\Scripts\python.exe -m uvicorn app.linkedin_fresh_jobs:app --host 127.0.0.1 --port 8000
    .\.venv\Scripts\python.exe -m app.fresh_watcher

The main worker searches on startup and then every
`LINKEDIN_POLL_INTERVAL_SECONDS` seconds (600 by default in current code). The
watcher searches the last `FRESH_WATCHER_LOOKBACK` seconds (120 by default) at
approximately `FRESH_WATCHER_INTERVAL` seconds (60 by default), with jitter
and retry/circuit-breaker behavior.

Check the main worker:

    Invoke-RestMethod -Uri 'http://127.0.0.1:8000/health'

The endpoint reports safe status metadata and does not expose secrets. The
watcher writes operational messages to its process output.

4. TEST AUTHENTICATED ENDPOINTS
-------------------------------

In a second PowerShell window:

    $token = (Select-String -Path .env -Pattern '^JOBIE_API_TOKEN=').Line.Substring('JOBIE_API_TOKEN='.Length)
    $headers = @{ Authorization = "Bearer $token" }

Read the in-memory result buffer without clearing it:

    Invoke-RestMethod -Uri 'http://127.0.0.1:8000/fresh-jobs?peek=true' -Headers $headers

Request a digest. This can send a real Telegram message when stored matching
jobs exist:

    Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/digest/send' -Headers $headers

Manual digest requests are rate-limited by `MANUAL_DIGEST_MAX_PER_DAY` and
`MANUAL_DIGEST_COOLDOWN_SECONDS`; reservations persist in Supabase. Confirm the
recipient before using this endpoint.

5. TEST THE SEPARATE IMPORT API
-------------------------------

Start it in another window:

    .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
    Invoke-RestMethod -Uri 'http://127.0.0.1:8001/health'

Submit a record without `posted_at` to avoid the recent-job alert:

    $job = @{ job_id = "manual-test-$([guid]::NewGuid())"; title = 'Jobie import test'; company = 'Example company'; url = 'https://example.com/jobs/test'; source = 'manual_test' } | ConvertTo-Json
    Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8001/jobs/import' -Headers $headers -ContentType 'application/json' -Body $job

The first request should report `imported=true`; submitting the same
`job_id` again should report `duplicate=true`. Requests without the bearer
token are rejected.

6. RENDER COMMANDS
------------------

Configure two Render Background Worker services with these start commands:

    python -m uvicorn app.linkedin_fresh_jobs:app --host 0.0.0.0 --port $PORT
    python -m app.fresh_watcher

Set `SUPABASE_DB_URL` and the worker-specific Telegram settings in each
service's environment. Do not put secrets in the repository. The optional
keep-alive workflow is best effort and is not a substitute for an always-on
Render plan.

7. AUTOMATED CHECKS
-------------------

Run the repository tests and syntax check:

    .\.venv\Scripts\python.exe -m unittest discover -s tests -v
    .\.venv\Scripts\python.exe -m compileall -q app scripts tests

Tests should not be expected to contact LinkedIn or Telegram unless explicitly
configured to do so. Verify real integrations separately with a controlled
account and recipient.
